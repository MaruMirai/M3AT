# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A RimWorld 1.7 mod ("M3AT: Maru's 3D Animated Toons", packageId `marumirai.M3AT`; formerly "IsoRim - Maru's Pawn Models") that adds on to the **IsoRim** mod (`Peren.IsoRim17`, Workshop id 3819577715). It replaces IsoRim's procedural pawn figure with an animated 3D model for every person IsoRim draws as a figure (`People.FigureRace`), colonist or not: standing, moving, sitting, lying (bed, ground, a building's couch, corpses), crawling, limping, wading and swimming. Statues, corpses gone to bones or in a gibbet, people floating upright in a vat and pawns another mod places (`Api.AttachedPlace`) fall through to IsoRim's own figure, as does anything but standing and walking for the baked (non-skinned) frames. It is an early prototype: only a few clothes have meshes, hair and beards are drawn on the skinned figure only, carrying (things and people) is on the skinned figure only, and a held weapon is IsoRim's 3D model of it (or, without one, its solid sprite slab) put in the drafted stance's hands (`WalkFigures.DrawWeapon`, skinned figure only), not yet aimed. Weapons not in hand (the equipped one undrafted, any in the inventory) are drawn on the body (`Source/Holsters.cs`). CE's melee and ballistic shields are held in the left fist while drafted (`Source/Shields.cs`). Headgear, masks and other head, face or neck apparel without a garment of its own here is not drawn: IsoRim's models are used only for worn equipment (packs, belts, lances and the like, `Source/WornGears.cs`).

Besides Harmony and IsoRim, `About/About.xml` lists two required mods, for the faces: [NL] Facial Animation (`Nals.FacialAnimation`, Workshop id 1635901197) and [NL] Facial Animation - Experimentals (`Nals.FacialAnimationExperimentals`, Workshop id 2581693737). The code still runs without them (a bare head, `Source/FaceLayers.cs`), so the requirement is only in the mod's metadata.

IsoRim's source and docs are in the installed Workshop copy, `~/.local/share/Steam/steamapps/workshop/content/294100/3819577715/` (source in `Source/`, mod API docs in `Docs/Api.md`). Read it to see how IsoRim's `People`, `Animals`, `Poses`, `Api` and `WeaponModels` behave, but don't edit it. It updates with the Workshop, and this mod compiles against it. `./check_isorim.sh` (run hourly by the systemd user timer `m3at-isorim-watch.timer`) notices an update, sends a desktop notification and writes a report to `~/.local/state/m3at-isorim/pending.txt`: the Api.Version, the files changed since the acknowledged copy in `baseline/` (the shaders `MarusSmooth` copies first) and a trial build against the new DLL. A session hook prints that report at the start. `./check_isorim.sh --ack` takes the installed IsoRim as the new baseline once it has been dealt with.

The game's own sprites (to model a garment after) are packed in each expansion's `Data/<pack>/Assets.zip` as zstd-compressed `.dds.split` files (Waylith's split BC7); `python3 anim_scripts/game_sprite.py <Assets.zip> <part of a texture path> <out folder>` writes them as PNGs.

## Layout

The mod as the game loads it is the folder `M3AT: Maru's 3D Animated Toons/` (`About/`, `LoadFolders.xml`, `1.7/Assemblies/`, `Defs/`, `Patches/`, `Shaders/`, `Models/chibi/`, `Models/wounds.png` and the fishing rod's `Models/tool_rod.obj`, `.mtl` and `fishing_line.obj`). RimWorld's `Mods/` folder has a symlink to that folder, not to the repository. Everything else at the repository's root is development only and is not shipped: `Source/`, `anim_scripts/`, the .blend and .glb files in the root `Models/` (the rig, `Models/garments/`, `Models/bases/`, `Models/unused/`, the old `Models/unused/p1`), `animDLs/`, `archive/`, `generationAssets/` (its scripts are in `anim_scripts/generation/`, their work left in `generationAssets/`, which is not in git, nor are `Models/unused/` and `previews/`), `weapon_sprites/`, the shell scripts and the TODO notes. Paths the game reads (`Models/chibi`, `Models/wounds.png`, `Defs/...`, `Shaders/...`) are relative to the mod's folder; tool paths (`Models/pawnHumanRig.blend`, `anim_scripts/...`) are relative to the repository's root. The C# namespace and the assembly are `M3AT`; the `Marus*` shader names keep the old name.

## Build

```
dotnet build Source/M3AT.csproj
```

The output goes to `M3AT: Maru's 3D Animated Toons/1.7/Assemblies/M3AT.dll`, which that folder's `LoadFolders.xml` loads. The csproj references the RimWorld, Harmony and IsoRim DLLs by absolute paths under `~/.local/share/Steam/...`. It compiles against the *installed* Workshop IsoRim.dll, not against `3819577715/`. There are no tests. Check changes by running the game.

Code that only does maths (the ragdoll solver, skinning, the garment and holster placing) can also be run outside the game. RimWorld 1.7 is a self-contained .NET 10 app (Waylith), and its `UnityStubs.dll` implements Unity's `Vector3`, `Quaternion` and `Matrix4x4` in plain C#. Only .NET 8 is installed system-wide, so a harness has to run on the game's own runtime. What has worked (the one harness kept is `anim_scripts/hairbuild/`, below; others are not kept):
- A harness csproj that compiles `Source/*.cs` plus a `Test.cs`, which can be a `partial class SkinnedFigure` for private access. It takes the mod csproj's references and sets `<AssemblyName>RimWorld</AssemblyName>`, `OutputType Exe`, `UseAppHost false` and `GenerateRuntimeConfigurationFiles false`.
- A scratch folder with symlinks to every file in the RimWorld install except `RimWorld.dll` (replaced by the harness's own) and the `RimWorld` launcher. The launcher must be copied, not symlinked, as a symlinked one could resolve back to the real install and start the game.
- IsoRim and Harmony loaded from their Workshop folders by an `AssemblyLoadContext.Default.Resolving` handler in `Main`.
- The chibi read with the private `ReadMesh`/`ReadAnim` rather than `Load`, which wants the garment textures, and `faceFrom = null` set before `NewPosed`. Posed meshes can be written as OBJ and rendered with Blender's Workbench to look at the poses.

Engine costs (read from the decompiled Waylith engine with `~/.dotnet/tools/ilspycmd`, not from docs; they are unlike real Unity's, so check them again after a game update). They are why `Source/GpuSkinning.cs` is built as it is:
- `Mesh.vertices`, `normals` and `colors32` setters clone the array. At the next use the engine rebuilds the whole mesh's CPU data, UVs and indices included, and works out the bounds twice, so an explicit `bounds` has to be set again after. Each changed mesh then gets new Vulkan vertex and index buffers.
- `Matrix4x4.MultiplyPoint3x4` and `MultiplyVector` transpose the whole matrix on every call.
- There is no frustum culling: every draw call given is drawn. IsoRim's `Cull` culls pawns and model parts itself.
- `MaterialPropertyBlock.SetVectorArray`/`SetMatrixArray` become per-draw storage buffers, copied when `Graphics.DrawMesh` is called. A GLSL `layout(std430, set = 2, binding = N) readonly buffer _Name { ... }` gets one by its block name. Arrays set on the material instead are last write per frame, as the binding is shared per material.
- A material's layout (uniforms, textures, storage slots) is parsed from the fragment shader's text, so a buffer that only the vertex stage reads must be declared in the fragment shader too.
- The engine's mesh carries only uv0..uv3 (each four floats) and tangents as extra vertex channels.
- IsoRim's own `DynamicModels.Submit` passes only its own floor block, and its `PartBatches` instancing would drop a block, so GPU-skinned parts go through `Api.SubmitFigureMesh` (Api 62), which takes our block, writes its floor and flash into it, and never batches.
- Shaders compile without the game running through the game's Slang: `Waylith.Rendering.RuntimeShaderCompiler.Compile(source, name, "main", RuntimeShaderLanguage.Glsl, stage)`, with the engine's variant defines (`USE_TEXTURE`, `INSTANCED`, `OUTLINE_MRT`) added after `#version`. `ShaderMetadataParser.ExtractMaterialLayout`, `ExtractVertexInputLayout` and `ValidateStageInterface` are public too. A shader that fails to compile in the game is drawn magenta.
- In the harness, reading `solid.EngineMesh` forces the rebuild without a GPU, but the cost of the Vulkan buffers can't be measured there.

## Asset pipeline (Blender → OBJ frames → game)

The model is not skinned at runtime. The animation is baked offline into one static posed OBJ per frame:

1. `anim_scripts/walk.py` generates the walk/run procedurally on the Rigify metarig (`metarig`) in a rigged .blend. Legs use 2-bone IK against a planted-foot path, which is then converted to FK keys. Gait parameters are module globals: `WALK` holds the defaults and `RUN` the run overrides, and `set_gait(g)` blends between them. Distances are in leg lengths.
2. `anim_scripts/export_frames.py` imports `walk`, bakes each gait level and writes the frames:
   ```
   /home/t/Programs/blender-5.2.3-linux-x64/blender -b Models/pawnHumanRig.blend --python anim_scripts/export_frames.py -- "M3AT: Maru's 3D Animated Toons/Models/chibi"
   ```
   The output is `idle.obj`, `walk_00..23.obj`, `run1_00..run6_23.obj` (run blended in by sixths), `<folder>.mtl` and `clip.txt` (frame count and ground covered per cycle for each gait). Three more loops go into `anim.txt` only: `sit` (`walk.sit_at`, `SIT_SECONDS`), `lie` (`walk.lie_at`, on the back but made upright, `LIE_SECONDS`) and `crawl` (`walk.crawl_at`, made upright (tipped back `CRAWL_TIP`, the game's 75° lay-down), by the ground covered, `crawl_ground_per_cycle` in `clip.txt`: one loop of a hands-and-knees mocap crawl from `anim_scripts/crawl_clip.json`, else the old belly crawl, `walk.belly_crawl_at`. `anim_scripts/import_crawl.py` (`blender -b --python anim_scripts/import_crawl.py -- <crawl.glb> [first last]`) writes that file from a glTF whose rig names its bones as the metarig does (Meshy's auto-rig on the chibi): each bone's turn from rest in armature space, `MAP` naming the glTF bone each metarig bone follows, the hips' offset from an even pace, and the leftover turn between the last frame and the first spread over the loop so it closes. 4. Hair: the mod ships no hair. Every hairstyle is built in the game from whichever hair textures the player has loaded (`Source/HairBuilder.cs`, below), so no other mod's art is copied into this one. `archive/hair.py` (`./archive/export_hair.sh <sprite folder> <out folder> [styles]`) is the older Blender version of the method, kept for reference only and no longer in step with `HairBuilder.cs`. Its output is made from that mod's art, so it must not go in this mod (`M3AT: Maru's 3D Animated Toons/Models/chibi/hair/` is gitignored and not read). The builder makes each hairstyle from its three sprites with no hand modelling. It takes the hair's own visual hull (the side sprite with the front and back sprites together, since each leaves out what the body hides) joined to the drawn-over head's, each slice of each cut to a superellipse. Filling the head into each outline instead leaves a block at the corners of the face that no sprite has hair at, which shows as a bald temple with a strand down the face. From `UnderChin` (0.4 head heights) above the drawn-over head's chin down, the hull in front of the head's middle is only where the front sprite has hair, as the back sprite's width with the side sprite's front locks filled the slice right across under the chin, a beard-like band joining the locks. Behind the head's middle the hull is only where the back sprite has hair (in rows where it has any), as the front sprite's wider spread left the back corners standing out past it, with the side sprite's outline ink on them or cut out as holes, but past either end of the back sprite's hair it narrows from the front's width at the middle to the back's at the back of the hair (`Tapered`), and that flank (`flank`) is the side sprite's alone (no say for the back sprite; a crown there takes the front one): cut to the back's width at once, the step faced backward past the back sprite's outline and was cut away as a hole over the ear (Gloomy Hair's LongA, LongE). Before any of it the sprites are lined up (`LinedUp`): many mods draw hair a few pixels off the image's middle the same way in both the front and back sprites, so read from behind (mirrored) the back one is off by twice that (Gloomy Hair, GOPNI's retexture: 3 to 8 px at 256); measured over the rows across the skull where both hug the head and both edges agree (`LineUp*`), each is moved half of it toward the head's middle; and the side sprite is moved back 2 to 4 px (`SideBack`) where its hair stops that far short of the back of a head the back sprite covers right across (LongF, middlB, WavelongB). Conventions that must stay consistent across the exporter and the C#:
- OBJ space is one unit = one map cell, +Y up, with the figure facing -Z. Blender's (x, y, z) is written as (-x, z, y). Triangle winding is written reversed because IsoRim's loader mirrors z.
- The figure is scaled so the idle pose is `FIGURE_HEIGHT` (1.25, the top of IsoRim's `person_head.obj`) tall. IsoRim's `People.FigureHeight` says 1.12, but its body and head meshes reach 1.25, so 1.12 comes out too small.
- The material is named `stuff_skin`. IsoRim tints materials whose names start with `stuff` with the colour passed to `DrawModel` (the pawn's skin colour).
- Face patches: the triangles are picked once in the standing pose. If the body has a `face` vertex group, that group is used. Otherwise the patch is the front-facing triangles dominated by the head bone (`walk.HEAD`, `spine.006`). UVs are a front projection in the head bone's frame, so they stay fixed per vertex and the face follows the head. They use Facial Animation's texture layout (eye line at v = 1 - 70.6/128), with `FACE_SPAN` and `FACE_EYES` setting the size and height. The patch is lifted `FACE_LIFT` cells along the normals. A `# centre x y z` comment gives the head's middle, which the C# grows each layer out from. FaceLayers reads these files with z flipped and the triangle order kept, as IsoRim's loader does.
- `clip.txt` keys are `frames`, `ground_per_cycle`, `run_levels`, `run_ground_per_cycle`, `crawl_ground_per_cycle`, `limp_ground_per_cycle`, `hop_ground_per_cycle`, `wade_ground_per_cycle` and `swim_ground_per_cycle`. If the run keys are missing, the C# falls back to walk only (as in `Models/unused/p1`, an older walk-only export).

## Runtime (WalkFigures.cs)

- The static constructor requires IsoRim `Api.Version >= 62` (`MinimumApi`: the custom figure renderer Api, Docs/Api.md part 43, `Docs/FigureApi-Migration.md`). The mod option `clothesOcclusion` (on by default, `SkinnedFigure.ClothesOcclusion`) leaves the redraw out for all but the skin too (`PieceMeshes.isSkin`: the body and the Furskin gene's fur), so clothes and hair take both. IsoRim's models on the figure (weapons, gear, head wear) and its outline still take them.
- Freecam (`Source/Freecam.cs`, any figure; keys in `Defs/KeyBindings.xml`, category M3AT): `M3AT_Freecam` (F6) flies a free eye in IsoRim's 3D view in place of its camera swung round a point on the ground. The game's `MapDolly_` keys move it along the ground the way it faces (not along the tilt), `M3AT_FreecamUp`/`Down` (Right Shift, Right Ctrl) straight up and down, eased (`Accel`), at `freecamSpeed` cells per real second (`BoostTimes` that while `M3AT_FreecamBoost`, Left Shift, is held, `Boost`), and with `freecamScrollFlies` (on by default) the mouse wheel too (`ZoomPrefix` on `CameraDriver.CameraDriverOnGUI` uses the scroll event, so the game's zoom is untouched; one opened in pointer mode frees it while up, closing as the game has it; a right click with nothing selected (the game's opening of the architect) goes into `pointerMode`, where left clicks go through to the map (the tab's `closeOnClickedOutside` off for that event, `KeepTabsOpen`), a right click with a designator in hand drops it, on the letter stack is the letter's (`OverLetters`, so closing one keeps pointer mode), with nothing selected goes back to looking at once (used up, the tab closed), and an order goes back once seen to open no orders menu (`rightPending`, the frame after release); with `freecamClickOffLooks` (off by default) a left click in pointer mode that leaves nothing selected goes back to looking (`leftPending`); relocking drops any box selection begun. Looking, the cursor is locked (`Cursor.lockState`, GLFW's disabled mode) and put back in the middle of the screen every frame (`Warp`: the engine window's `CursorPos`, `RimWorldWaylith.Bootstrap._inputBridge`'s `_lastCursorPos`, which clicks are sent from, and `InputSystem.QueueMouseMove`, all by reflection but the last), the movement read as the offset from there, so clicks land under the cross drawn there (`GuiPostfix`); it is freed while a float menu, dialog or main tab wants the pointer or the game is unfocused (`PointerWanted`), and then warped for `CentreFrames` frames: back to where it was when looking began (`KeepLookedFrom`, `lookedFrom`) on going into pointer mode or leaving the freecam with `freecamPointerBack` (on by default), else (a dialog, the game unfocused) to the middle. It needs IsoRim's Api 68 (`MinimumApi`; off with a warning before that) and uses no IsoRim internals: the eye is a camera pose (`Api.PushViewPose`, Api 66, pushed on `Enter` and disposed on `Leave`, `Posing`, the only code naming the camera Api's types), so IsoRim's rays, cell picking, view rect, culling, fog and sky follow, its focus distance the ground at the screen's middle within `NearDistance`..`FarDistance` (`FocusDistance`), looking up to `LeastPitch`; `Frame` (on `Api.BeforeViewUpdate`) runs the keys, flying and looking; IsoRim's own camera keys and look drag wait meanwhile (`BlockPlayerCamera`), its settings are never written, and on leaving `Api.SetPlayerView` turns its camera to the freecam's yaw; the 3D view switch, the cutscene lock, leaving first person and held keys are Api 68's (`View3DActive`, `ControlsLocked`, `LeaveFirstPerson`, `KeyHeld`, `PerspectiveTanHalf`); first person coming on while flying (`Api.FirstPersonOn`, Api 71, `FirstPersonOn`; before it IsoRim's key, `R3D_FirstPerson`, and a copy of its selection test, `FirstPersonStarts`) sets the freecam aside for it, as a pose would otherwise win over first person; Resume brings it back the next frame if first person didn't start. - Faces (FaceLayers.cs) follow IsoRim's `FaceDecal` and the sibling mod `../IsoRim Nals Experimentals Patch`. With Facial Animation active, the pawn's FA part nodes are found by reflection and sorted by `baseLayer`. The head's Basic layer and the whole-sprite skin layer are skipped because they carry the sprite outline. The head's Cover/Highlight layers and see-through skin overlays are kept. The master's `UpdateAnimation` is called once a tick. Each layer's `MatSouth` is copied into one of this mod's materials (`Defs/ShaderDefs/MarusFace_Shaders.xml`, `Shaders/MarusFace.*.glsl`, taken from that patch). These keep the game shader's colour maths but shade by IsoRim's sun like the head. FA's own materials are unlit, so its skin-coloured eyelid cover would show as a brighter patch round the eyes. The lid's Cover layer is a special case (mode 5). FA paints it from the sprite head's own art (its shading, plus `CutoutSkin`'s red shadow tint), so only its shape is kept: skin colour × the lid mask, with the colour rounded like IsoRim's head tint. Layers are queued at 2950 + their place, before IsoRim's light pass (3099). The mouth is drawn on a copy of the patch with its UVs zoomed. A missing eye (`MissingEyes`: FA's eye labels for the race, `GetMissingPartsCommonAncestors`, a prosthetic not missing) leaves its half of the face texture out of the eyeball and lid layers (`_EyeCut` in `MarusFace.frag.glsl`; the "right eye" is the texture's right half, as FA's eyeball mask colours it, unless FA's `SwitchLeftAndRightEyes`), and that half gets FA's closed lid instead (`ClosedLid`: the lid controller's `graphicList` by layer, `GetSubGraphic` with the `close` LidShapeDef, as when it blinks). FA colours a hurt or blind eye (by its part efficiency) only when it loads its textures (at load, or when the face is changed), so `FaceLayers.PatchEyes` postfixes `HediffSet.DirtyCache` and, when either eye's health has changed (`eyeHealth`), calls the eyeball controller's `SetDirty` and `ReloadIfNeed`; this mends FA's sprite face too. The eye colour genes (`Eyes_Red`, `Eyes_Gray`) come through the same way: FA colours the eyes from its `EyeballColorDef`s, also only when it loads its textures, so `GenesPostfix` on `Pawn_GeneTracker.Notify_GenesChanged` reloads them, and `Patches/EyeGenes.xml` (in the mod's folder) replaces FA's two colours, as its red comes out pink on its dark art. Without FA, or for an export with no `face_*.obj`, the head stays bare. A pawn with the Furskin gene is drawn covered in fur, so Experimentals' blush for being naked would look wrong: `FaceLayers.PatchBlush` postfixes `FAHelper.GetThoughts` to leave its naked thoughts out (`NakedBlush`) of what Facial Animation picks its animations by; the mood is untouched. `Source/FaceTuning.cs` is a window for moving Facial Animation's face and mouth about on the patch in game, to find the numbers to bake into `FaceLayers` (`FacePivot`, `MouthRaise`, `MouthZoom`) or the exporter (`FACE_EYES`, `FACE_SPAN`); not saved, and hidden unless built with `-p:DefineConstants=FACE_TUNING` (then a dev-mode debug action, M3AT > Face tuning window, and a button in the mod options).

## Style

Match the existing voice: comments are plain-English sentences that explain *why* and what units are in use (cells, cells per game second, leg lengths), and C# uses explicit types with `Tag`-prefixed `Log` messages. Workshop-facing text (`About/About.xml` in the mod's folder) avoids jargon.
